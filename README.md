# Панель мониторинга доступности сетевых устройств (D4NMS)

Веб-панель, которая опрашивает список сетевых узлов и показывает их статус:
онлайн / офлайн / деградация, задержку, uptime за 24 часа и историю проверок.

**Сейчас работает на моках** — данные генерирует мок-движок, реальный пинг
не выполняется. Интерфейс и API при этом настоящие: при переходе на реальный
мониторинг меняется только один файл (`src/lib/mock-engine.ts`).

## Стек

- Next.js 15 (App Router) + React 19 + TypeScript
- Без внешних UI-библиотек: стили — чистый CSS, график — чистый SVG

## Запуск

```bash
npm install
npm run dev        # разработка: http://localhost:3000
npm run build      # production-сборка
npm start          # запуск production-сборки
```

## Что умеет панель

- Сводные карточки: всего / онлайн / офлайн / деградация / средняя задержка
- Таблица устройств: статус, задержка, uptime 24 ч, полоса последних проверок
- Автоопрос по таймеру (3 / 5 / 10 / 30 с) + пауза + кнопка «Проверить все»
- Фильтры: поиск, вкладки по статусу, фильтр по группе
- Карточка устройства (клик по имени): график задержки, статистика, история проверок
- Добавление / отключение / удаление устройств, внеплановая проверка одного узла
- Лента событий: падения, восстановления, деградация

## API (Next.js Route Handlers)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/status` | Снимок всех устройств и событий (без нового опроса) |
| POST | `/api/poll` | Раунд опроса всех включённых узлов → обновлённый снимок |
| POST | `/api/devices` | Добавить устройство |
| PATCH | `/api/devices/:id` | Включить/отключить мониторинг (`{ enabled }`) |
| DELETE | `/api/devices/:id` | Удалить устройство |
| POST | `/api/devices/:id/check` | Внеплановая проверка одного узла |

## Как заменить моки на реальный мониторинг

1. В `src/lib/mock-engine.ts` заменить `simulateCheck()` на реальную проверку:
   TCP connect через `node:net` с таймаутом 2000 мс (или ICMP ping) и
   классификацию ошибок: таймаут / connection refused / DNS / unreachable.
2. In-memory `Map` заменить на SQLite/PostgreSQL (таблицы `devices`, `checks`).
3. Фоновый опрос: вместо клиентского таймера — серверный cron/очередь
   (например, `setInterval` в instrumentation или отдельный воркер).

Типы (`src/lib/types.ts`), API-роуты и интерфейс при этом не меняются.
